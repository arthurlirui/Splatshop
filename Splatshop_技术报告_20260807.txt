第1章  项目概述
================================================================================

1.1 项目定位
────────────────────────────────────────────────────────────────

Splatshop 是一个高效的大型 3D Gaussian Splatting (3DGS) 模型编辑器，旨在对
高斯泼溅模型进行编辑、清理、组装和场景创作。该项目发表于 Computer Graphics
Forum 2025，目前处于学术原型 (Alpha) 阶段。

1.2 核心能力指标
────────────────────────────────────────────────────────────────

  • 桌面端: 支持最多 1 亿个 splats
  • VR 模式 (RTX 4090): 支持约 1000 万个 splats
  • 纯 C++/CUDA 实现，无需 Python 运行环境
  • CUDA Driver API: 内核代码可像着色器一样热编辑和热重载

1.3 技术栈概览
────────────────────────────────────────────────────────────────

  | 层级       | 技术                              |
  |------------|-----------------------------------|
  | 语言       | C++23, CUDA (NVRTC JIT 编译)      |
  | 图形 API   | OpenGL 4.5 (桌面) + OpenVR (VR)   |
  | 深度学习   | LibTorch 2.6+ (4DGS 变形网络)     |
  | GUI        | Dear ImGui + ImPlot + ImGuizmo    |
  | 数学库     | GLM, 自研四元数运算                |
  | 构建系统   | CMake 3.22+                       |
  | 平台       | Windows (VS 2022) / Linux (GCC 14)|

1.4 已实现功能
────────────────────────────────────────────────────────────────

  • 撤销/重做 (Undo/Redo)
  • VR 查看和编辑 (OpenVR/SteamVR)
  • 笔刷/球形/矩形选择，笔刷/Del 删除
  • 选取节点或 splats 的平移/旋转/缩放
  • 绘制/上色 (Painting)
  • 透视校正高斯 (perspective-correct gaussians)
  • 3 点对齐工具

  • 图层管理 (复制 Ctrl+D, 合并 Ctrl+E)

  ★ 以下为近期 (2025-2026) 新增功能:
  • 渐进式点云渲染器 (Skye 算法实现)
  • 4DGS 动态场景加载与播放 (HexPlane + MLP 变形)
  • 远程控制 HTTP API (FastAPI + JSON-RPC)
  • 对象运动控制 + 骨骼蒙皮 (LBS + 52 ARKit blendshape)
  • VR 远程观看 (WebXR 客户端 + NVENC 视频流)
  • OrbbecSDK RGBD 相机集成
  • 场景 Splats 创建/加载/删除/着色 API

2.1 SplatEditor 主类结构
────────────────────────────────────────────────────────────────

  SplatEditor 是一个 C++ struct (约 528 行)，作为应用程序的中央控制枢纽，
  通过静态单例 SplatEditor::instance 访问。核心成员如下:

  ┌─────────────────────────────────────────────────────────────┐
  │  SplatEditor                                                │
  │  ┌──────────────┐  ┌──────────────┐  ┌───────────────────┐ │
  │  │ Scene scene   │  │ CUDA Programs│  │ OpenVRHelper* ovr │ │
  │  │ (场景图)      │  │ (7 个模块)   │  │ (VR 集成)         │ │
  │  └──────────────┘  └──────────────┘  └───────────────────┘ │
  │  ┌──────────────┐  ┌──────────────┐  ┌───────────────────┐ │
  │  │ 历史记录      │  │ 资产库       │  │ 设置 + 状态      │ │
  │  │ (undo stack)  │  │ (AssetLib)   │  │ (settings/state)  │ │
  │  └──────────────┘  └──────────────┘  └───────────────────┘ │
  │  ┌──────────────┐  ┌──────────────┐  ┌───────────────────┐ │
  │  │ Timeline     │  │ RiggedCtrl   │  │ RemoteStereo     │ │
  │  │ (关键帧)     │  │ (蒙皮动画)   │  │ (远程VR状态)     │ │
  │  └──────────────┘  └──────────────┘  └───────────────────┘ │
  └─────────────────────────────────────────────────────────────┘

  7 个 CUDA 可执行程序模块 (CudaModularProgram):
    • prog_gaussians_rendering  — 3DGS 泼溅渲染内核
    • prog_gaussians_editing    — 笔刷编辑内核
    • prog_points               — HQS 点云渲染器
    • prog_progressive_points   — 渐进式点云渲染器 ★
    • prog_triangles            — 三角形网格渲染
    • prog_lines                — 线段渲染
    • prog_helpers              — 辅助/调试内核
    • prog_skinning             — 骨骼蒙皮内核 ★

2.2 渲染管线 (draw 流程)
────────────────────────────────────────────────────────────────

  SplatEditor::draw() 每帧执行的渲染步骤:

  Step 0: 蒙皮调度
    rigController.dispatchSkinning(scene) — 如有 SNRiggedSplats 节点

  Step 1: 4DGS 变形 ★
    收集所有 SN4DGSSplats 节点
    → node->deform(t, mainstream)    // 推入 LibTorch 正向传播
    → node->swapToDeformed()          // 交换指针到变形输出缓冲
    → 记录 deformEvent 供后续流等待

  Step 2: 收集可渲染节点
    scene.forEach<SNPoints>, scene.forEach<SNTriangles>

  Step 3: 逐目标并行渲染 (每个 RenderTarget 有独立 CUDA 流)
    3a. 等待 deformEvent (如有 4DGS 变形)
    3b. 清空帧缓冲
    3c. 点云渲染 (分流):
        • HQS 路径: 逐点原子深度/颜色写入
        • Progressive 路径 ★: 4 阶段流水线
    3d. 3DGS 瓦片渲染:
        预过滤 → 排序 → 瓦片分配 → 正向渲染 → EDL 后处理
    3e. 三角形渲染

  Step 4: 恢复 4DGS 规范态
    node->swapToCanonical() — 渲染完成后恢复原始指针

  ConcurrentTarget 结构 (每渲染目标):
    • 独立 CUDA 主流/副流
    • 虚拟内存: 深度缓冲, 颜色缓冲, 瓦片列表, splat 索引,
      暂存数据, 排序缓冲, 瓦片片段计数, 几何边界
    • 主机可读计数器: numVisibleSplats, numFragments

  ProgressiveTarget 结构 (每渲染目标) ★:
    • indexImage       — 每像素 uint32 (0xFFFFFFFF = 空)
    • reprojectBuffer  — ProgressiveVertex[] 局部空间可见点
    • indirect         — ProgressiveIndirectCommand 原子计数
    • 固定主机镜像     — 零拷贝读取间接计数
    • CUDA 事件         — evFillStart/evFillEnd (自适应预算计时)
    • pointsPerMs      — 吞吐量估算

2.3 更新管线 (update 流程)
────────────────────────────────────────────────────────────────

  SplatEditor::update() 每帧执行的步骤:

  1. cuCtxSynchronize()          — 同步 CUDA 上下文
  2. 更新窗口标题 (FPS 显示)
  3. TWEEN::update()             — Tween 动画系统推进
  4. timeline.update(scene, dt)  — 关键帧时间线 ★
  5. 4DGS 自动回放 ★            — 如无时间线但有 4DGS 节点
  6. rigController.update(scene) — 骨骼蒙皮姿态更新 ★
  7. ImGui 新帧
  8. Runtime::timings.newFrame() — 重置滑动窗口计时
  9. scene.updateTransformations() — 场景变换传播
  10. 重置每帧计数器
  11. 构建各内核的 CommonLaunchArgs
  12. 零初始化设备状态计数器
  13. 拖放预览位置更新
  14. uploadSplats()             — 异步上传新加载的 splat 数据
  15. uploadPoints()             — 异步上传点云数据 ★
  16. Orbbec 实时点云上传 ★      — SNOrbbec 帧就绪标志
  17. VR 姿态更新                — OpenVR HMD/控制器跟踪
  18. 远程立体视图模式设置 ★     — 三种姿态空间
  19. inputHandling()            — 桌面/VR 输入分发
  20. 异步线段上传

2.4 CUDA 模块化程序设计
────────────────────────────────────────────────────────────────

  文件名: include/CudaModularProgram.h

  系统基于 NVRTC (编译) + nvJitLink (链接) 构建 JIT 编译流水线。

  CudaModule (单个 .cu 源文件):
    • 路径/名称, LTOIR 数据
    • compile() 方法:
      - 读取源文件
      - 自动检测 GPU 计算能力
      - 编译选项: --use_fast_math, --extra-device-vectorization,
        -lineinfo, --std=c++20, --relocatable-device-code=true,
        --dlink-time-opt, --split-compile=0 (全核)
      - 生成 LTOIR 中间表示

  CudaModularProgram (完整链接程序):
    • 管理多个 CudaModule
    • link() 方法:
      - nvJitLink: -dlto, -arch=sm_XY, -O3
      - 添加所有模块的 LTOIR 数据
      - cuModuleLoadData 加载最终 cubin
      - 枚举所有内核入 kernels 映射 (unordered_map<string,CUfunction>)
    • 启动 API:
      - launch(name, args, count) — 自动计算网格尺寸
      - launch(name, args, settings) — 显式网格/块 + 可选流 + 计时
      - launchCooperative(name, args, ...) — 协作组
      - fromCubin(cubin, size) — 从预编译 cubin 加载
    • 热重载: monitorFile 监视源文件变化 → 自动重编译 + 重链接
    • 计时系统: EventPool 回收 CUevent, 异步解析内核用时

3.1  渐进式点云渲染器 ★
================================================================================

3.1.1 理论基础
────────────────────────────────────────────────────────────────

  基于 Schütz et al. (2019): "Progressive Real-Time Rendering of One
  Billion Points Without Hierarchical Acceleration Structures" (TU Wien)。
  参考实现: Skye 项目 (E:\Code\Skye, OpenGL 4.5 + V8/JS)。
  Splatshop 以 CUDA 重建全管线，复用现有的 (depth<<32)|color 帧缓冲约定。

  核心技术: 素数同余置换 (prime-congruence permutation)
  ──────────────────────────────────────────────────

  性质: 对于任意素数 p ≡ 3 (mod 4)，映射 f(n) = n² mod p 是 [0, p) 上的
  二次双射 (bijection)，且 f(f(n)) 同样为双射。

  应用: 对点云中每个点索引 i，计算目标槽位:
    slot = permuteI(permuteI(i, prime), prime)
  其中 permuteI(n, p) = (n * n) % p (uint64 防溢出)。

  结果: 在置换后的缓冲区中，从偏移 fillOffset 开始连续顺序绘制，相当于
  对整个点云进行均匀随机采样。无需层次加速结构，每帧开销仅受填充预算限制。

3.1.2 数据结构
────────────────────────────────────────────────────────────────

  ProgressivePointData (设备端 POD):
    count, numBuffers, maxPointsPerBuffer = 134,000,000
    position[8]  — vec3* 数组，每块缓冲区指针
    color[8]     — uint32* 数组
    prime        — uint64 置换素数
    fillOffset   — uint32 实时填充游标 (环绕 [0, count))
    ready        — bool (distribute 完成后置 true)

  ProgressiveVertex (20 字节, 重投影缓冲条目):
    {ux, uy, uz, color, index}
    位置存储在局部空间，每帧重投影时重新应用节点的世界变换。

  ProgressiveIndirectCommand (间接绘制命令):
    {count, primCount, firstIndex, baseVertex, baseInstance}
    与 Skye 的 5-uint 布局兼容，仅 count 被使用。

  ProgressivePointCloud (主机端):
    vm_position[8], vm_color[8]  — CudaVirtualMemory 块
    init(numPoints): 计算素数 → 分配虚拟内存 → 物理提交
    largestPrimeCongruent3mod4(n): Skye 的 previousPrimeCongruent3mod4 的 C++ 版本
    限制: 最多 8 * 134M ≈ 10.7 亿点

3.1.3 五阶段流水线
────────────────────────────────────────────────────────────────

  所有内核位于 src/render/progressive_points.cu

  ┌─────────────────────────────────────────────────────────────────┐
  │ 加载时 (一次性)                                                  │
  │ Stage 0: kernel_progressive_distribute                          │
  │   每个规范态点 → 置换索引 → 写入分块缓冲区                        │
  │   完成后 ProgressivePointData.ready = true                      │
  └─────────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────────┐
  │ 每帧:                                                            │
  │ Stage 1: kernel_progressive_clear_index                         │
  │   将每像素索引图清零 (0xFFFFFFFF = "无点")                        │
  │                                                                  │
  │ Stage 2: kernel_progressive_reproject                           │
  │   对上一帧 reprojectBuffer 中的每个可见点:                        │
  │   重新应用当前世界变换 MVP 矩阵                                   │
  │   → atomicMin 写入 framebuffer ((depth<<32)|color)              │
  │   → 写入 indexImage[pixelID] (最前点)                           │
  │                                                                  │
  │ Stage 3: kernel_progressive_fill                                │
  │   对预算数量个线程，读取置换缓冲中 (fillOffset+i)%count 位置的点  │
  │   → 投影 → 写入 framebuffer + indexImage                        │
  │   主机推进 fillOffset                                            │
  │                                                                  │
  │ Stage 4: kernel_progressive_reset_indirect (单线程)             │
  │   清零 indirect->count                                           │
  │                                                                  │
  │ Stage 5: kernel_progressive_create_vbo                          │
  │   对每个帧缓冲像素: 从 indexImage 读取全局点 ID                   │
  │   → atomicAdd(&indirect->count, 1) 获取压缩槽位                  │
  │   → 从渐进式云获取局部空间位置 + 颜色                            │
  │   → 写入 reprojectBuffer[slot]                                  │
  │   最终计数即为下一帧 indirect->count                             │
  └─────────────────────────────────────────────────────────────────┘

3.1.4 自适应帧预算
────────────────────────────────────────────────────────────────

  kernel_progressive_compute_fill:
    • 输入: 重投影耗时 (ms, 来自 CUDA 事件), 填充耗时, 目标帧时间,
            吞吐量估算 (points/ms)
    • 计算: remaining = (targetMs - elapsedMs) * pointsPerMs
    • 钳制: [minFill, numPoints]
    • 自调节: 如重投影+固定填充便宜 → 本帧多花点; 如昂贵 → 少画点

3.1.5 加载器
────────────────────────────────────────────────────────────────

  BINPointCloudLoader (src/loader/BINPointCloudLoader.h):
    Skye 快速路径, .bin = 16 字节/点 {float x/y/z, uint8 r/g/b/a} LE
    分离 jthread 流式加载, 500K 点/批
    转换交叉格式到分离的 position/color 布局

  PointCloudPlyLoader (src/loader/PointCloudPlyLoader.h):
    通用点云 PLY (区别于 GSPlyLoader 的高斯泼溅 PLY)
    通过 scale_0/rot_0/f_dc_0 属性检测高斯泼溅 PLY 并拒绝
    支持 ASCII 和 binary_little_endian, uint8/uint16 颜色
    防御式解析, 损坏行跳过

3.1.6 GUI 面板
────────────────────────────────────────────────────────────────

  src/gui/pointcloud.h:
    • 渲染器单选: HQS vs Progressive
    • 渐进式控件: 填充预算滑块 (10K–30M), 点大小,
      自适应预算复选框 + 目标帧时间, 重置按钮
    • 每节点统计: 加载/上传点数, 包围盒, VRAM

3.2  4DGS 动态场景支持 ★
================================================================================

3.2.1 理论基础
────────────────────────────────────────────────────────────────

  Splatshop 支持 hustvl/4DGaussians 训练的 4D Gaussian Splatting 动态场景。

  4DGS 将动态场景表示为两部分:
    ① 规范态高斯 (canonical Gaussians): 标准 .ply 文件 (静止姿态的 3DGS)
    ② 变形场 (deformation field): HexPlane 六平面网格 + MLP 多层感知机,
       对每个时间步, 将规范态高斯位移到动态姿态

  变形网络输入: 规范态 position, scale, quaternion, opacity + 时间 t
  变形网络输出: 变形后 position, scale, rotation, [opacity]
    (Splatshop 将 opacity 存储在 color 中, 不单独消费变形 opacity)

3.2.2 场景节点: SN4DGSSplats
────────────────────────────────────────────────────────────────

  文件: src/scene/SN4DGSSplats.h (179 行) / .cpp

  SN4DGSSplats 继承 SNSplats:

    规范态高斯: dmng.data (继承自 SNSplats, 由 GSPlyLoader 加载)

    Deform4DGSConfig:
      shDegree       = 3       (SH 阶数)
      nGaussians     = 0       (高斯总数)
      formatVersion  = "1.0"   (格式版本)
      → loadFromFile(jsonPath) 从 config.json 解析

    Deform4DGSBuffer (设备端变形输出缓冲):
      vm_deformedPosition, vm_deformedScale, vm_deformedRotation
      cptr_deformedPosition/Scale/Rotation — CUdeviceptr 原始指针
      allocDevice(numSplats) / freeDevice()

    变形模块 (TorchScript):
      #ifdef SPLATSHOP_HAS_LIBTORCH
        std::unique_ptr<torch::jit::script::Module> deformModule;
      #else
        std::unique_ptr<void, void(*)(void*)> deformModule;  // 桩
      #endif

    状态:
      currentTime          = 0.0f     (归一化时间 [0,1])
      needsRecompute       = true     (原子标记, 编辑后强制重算)
      deformationEnabled   = true     (变形开关, 关=看规范态)
      canonicalPosition    = nullptr  (保存的规范态指针)
      canonicalScale       = nullptr
      canonicalQuaternion  = nullptr

3.2.3 LibTorch 集成架构
────────────────────────────────────────────────────────────────

  依赖隔离:
    • 仅 SN4DGSSplats.cpp 包含 <torch/script.h>
    • 所有 4DGS 代码由 #ifdef SPLATSHOP_HAS_LIBTORCH 守卫
    • 若无 LibTorch: 桩实现 (节点变成直通, 规范态=变形态, 打印警告)

  正向传播管线 (runDeformation):
    ① 从 dmng.data 提取规范态数据为 CUDA 设备指针
    ② torch::from_blob(ptr, sizes, torch::kCUDA) — 零拷贝包装
       (直接指向 Splatshop 自己的 CUDA 缓冲区, 不复制)
    ③ 传入: positions, scales, quaternions, 中性 opacity, time
    ④ deformModule->forward(inputs).toTuple() — TorchScript 执行
    ⑤ cuMemcpyDtoDAsync — 将输出复制到 Deform4DGSBuffer
       (所有操作在同一 CUDA 流上异步完成)

3.2.4 指针交换机制
────────────────────────────────────────────────────────────────

  swapToDeformed():
    保存 dmng.data.position/scale/quaternion → canonicalPosition 等
    回填 dmng.data.position/scale/quaternion → deformedBuffer 的指针
    → 渲染内核现在读取变形数据 (无需修改内核代码)

  swapToCanonical():
    恢复 dmng.data.position/scale/quaternion → canonicalPosition 等
    → 渲染完成后数据回到规范态

  流同步:
    deform() 在 mainstream 上排队 cuMemcpyDtoDAsync
    → 记录 CUDA 事件 deformEvent
    → 每个渲染目标的流在执行 staging 内核前等待 deformEvent
    → 保证变形复制完成后再开始读取

3.2.5 增量计算优化
────────────────────────────────────────────────────────────────

  变形仅在以下情况重新计算:
    • currentTime 变化超过 1e-6 (时间步进)
    • needsRecompute 被设置为 true (编辑规范态后)
    • 首次加载

  deform() 开头检查: 若时间和 dirty 标志均未变化 → 直接返回 (无操作)

3.2.6 编辑工作流
────────────────────────────────────────────────────────────────

  ① 暂停时间线 → 变形网络停在当前帧
  ② 用现有工具选择/删除/绘制规范态高斯
  ③ 自动设置 needsRecompute = true
  ④ 恢复播放 → 下一帧重新变形, 编辑反映到所有后续帧
  ⑤ 关闭 deformationEnabled → 临时查看/对比规范态

3.3.1 总体架构
────────────────────────────────────────────────────────────────

      ▼

    • 控制: 小包高频姿态 + 低频命令 (通过本 API)
    • 视频: 独立帧流管道 (OBS/WebRTC/NVENC, 不经过此 API)

3.3.2 C++ 端设计
────────────────────────────────────────────────────────────────

  remote::RemoteControlServer (src/remote/RemoteControlServer.h):

    start(port = 7654):
      • 绑定 127.0.0.1:port (仅 loopback, 安全)
      • 生成分离的监听线程
      • 每个连接生成分离的处理线程 (支持并发客户端)

    listenerMain(port):
      accept 循环 → 为每个客户端套接字生成线程

    handleConnection(sock):
      while 读取一行 → JSON 解析 → 主线程调度 → 写响应
      (单次往返, 非持久连接)

  主线程调度 (核心模式):
    runOnMainThread(id, cmd, args):
      • 创建 std::promise<json> + std::future<json>
      • schedule([promise, handler, args]{ ... })
        → 利用 EventQueue 将 lambda 入队到渲染线程
      • 渲染循环每帧排空 EventQueue
      • 套接字线程阻塞 fut.wait_for(10s)  → 响应在一个帧内返回 (~16ms)
      • 10 秒超时: 看门狗保护主线程

  实现了 27 个命令处理器。

3.4.2 MotionTypes.h — 共享数据结构
────────────────────────────────────────────────────────────────

  TransformSample — 分解 T·R·S 的变换 (带 toMatrix/fromMatrix)

  JointPose — 关节局部空间姿态 {rotation(四元数), translation(vec3), scale(vec3)}

  SkeletonPose — 整骨架姿态 (vector<JointPose>)

  FaceData — 52 元素 ARKit 兼容 blendshape 权重数组

  EaseMode 枚举 — Linear / EaseIn / EaseOut / EaseInOut + applyEase()

  自研四元数数学库 (避免 GLM 的 gtc/quaternion 无法干净编译标量参数的问题):
    quatIdentity, quatMul, slerpQuat, quatToMat4, quatFromMat4,
    quatToEulerXYZ — 全部使用 std::sin/std::cos

3.4.3 MotionController — 刚体运动
────────────────────────────────────────────────────────────────

  静态方法类, 通过 node->transform 写入节点局部变换:

  绝对设置: setTransform, setTranslation, setRotation, setScale
  相对变异: translate (累加平移), rotate (预乘局部旋转), scaleBy
  获取: getTransform → TransformSample (分解 node->transform)

  setTransformAnimated:
    • 使用 Tween 系统从当前平滑过渡到目标
    • durationSeconds 持续时间 + EaseMode 缓动模式
    • 内插: 平移 mix(), 旋转 slerpQuat(), 缩放 mix()
    • dispatchKeyframeToMainThread(): 若从非主线程调用, 排队到 EventQueue

3.4.4 Timeline — 关键帧播放器
────────────────────────────────────────────────────────────────

  纯 CPU 驱动, 无需每帧 CUDA 调度:

  内部数据:
    vector<TransformTrack> — 每条轨道绑定一个 NodeID
      vector<TransformKeyframe> — 按时间排序的关键帧

  插值模式: Step / Linear / Slerp (四元数感知旋转 + 线性其他)

  update(scene, dt):
    推进 playhead → 每条轨道采样 → MotionController::setTransform 写入
    支持 loop 模式 + 自动停止
    Start/stop/reset/scrub API

  JSON 加载器 (loadTracksFromJSON):
    解析节点名 (通过 scene.find() 查找), 插值模式, 关键帧
    四元数 [x,y,z,w] 数组, 向量 [x,y,z] 数组

3.4.5 RiggedHumanController — 骨骼动画
────────────────────────────────────────────────────────────────

  每帧流程:

    ① setPose/setFace/setJointPose/setBlendshape → 写入期望姿态 + face
       → poseDirty = true
    ② update(scene):
       对每个脏节点:
         • 累加关节局部姿态: M_global[i] = M_global[parent] * M_local[i]
         • 计算蒙皮矩阵: M_skin[i] = M_global[i] * IBP[i] (IBP=逆绑定姿态)
         • cuMemcpyHtoD → 上传蒙皮矩阵
    ③ dispatchSkinning(scene):
       对每个脏 SNRiggedSplats 节点:
         启动 kernel_skin_splats → 写入 dmng.data 缓冲

3.4.6 ProceduralRigSource — 测试工具
────────────────────────────────────────────────────────────────

  在 splat 包围盒内沿 Y 轴堆叠 5 关节骨架:
    root → spine → chest → neck → head
  每个 splat 按 Y 高度绑定到最近关节 (单骨骼权重 = 1.0)
  分配: 设备端静止副本 + 蒙皮矩阵缓冲 + 骨骼索引/权重

  用于验证蒙皮管线无需真实绑定资产。

3.4.7 skinning.cu — CUDA 蒙皮内核
────────────────────────────────────────────────────────────────

  kernel_skin_splats — 每 splat 线性混合蒙皮 (LBS):

  输入: 静止姿态 position/scale/quaternion, boneIndices, boneWeights

  位置: 加权混合 M_skin[i] * restPos
  旋转/缩放: 加权混合 3x3 旋转 + 缩放提取
        → 混合 3x3 → 四元数 → qDeformed = qBlend * qRest

  可选面部 blendshape: 用 faceWeights 累加 delta (position/rotation/scale)

  限制: 每 splat 最多 4 根骨骼, 每 blendshape 10 个 float

  输出: 直接写入 dmng.data 缓冲 (原地变形)

3.7  场景 Splats CRUD API ★
================================================================================

3.7.1 总览
────────────────────────────────────────────────────────────────

  此 API 将场景 Splats 的创建、加载、删除和着色能力以 HTTP 端点暴露,
  便于 Python 程序和远程客户端以程序化方式操控 Splatshop 场景内容。

3.7.2 实现端点
────────────────────────────────────────────────────────────────

  A. POST /scene/splats/create — 从原语创建 splats

    请求体:
      {
        "type": "sphere" | "box" | "points",
        "params": { ... }  // 类型相关参数
      }

    SphereParams (球体):
      {
        "radius": 1.5,           // 半径
        "count": 500,            // splat 数量
        "color": [1.0, 0, 0, 1] // RGBA
      }

    BoxParams (立方体):
      {
        "size": [2.0, 1.5, 1.0],
        "count": 800,
        "color": [0, 1.0, 0, 1]
      }

    PointsParams (点集):
      {
        "positions": [[0,0,0], [1,1,1], ...],  // N 个点位置
        "color": [0, 0, 1.0, 1]                // 统一颜色
      }

    响应:
      {
        "id": 15,           // 新节点 ID
        "name": "Sphere_0", // 自动生成名称
        "type": "SNSplats"
      }

  B. POST /scene/splats/load — 加载文件

    请求体:
      {
        "path": "C:/models/bicycle.ply",  // 或相对路径
        "type": "ply" | "scene_json"     // ply = 高斯泼溅, json = 场景描述
      }

    响应:
      {
        "id": 16,
        "name": "bicycle.ply",
        "numSplats": 2_347_890,
        "loaded": true
      }

  C. DELETE /scene/node/{id} — 删除节点

    无请求体, 返回:
      {
        "removed": true,
        "was": { "id": 15, "name": "Sphere_0" }
      }

  D. POST /scene/splats/{id}/color — 设置颜色

    请求体:
      {
        "color": [1, 0, 1, 1]  // 统一 RGBA 应用于所有 splat
      }

    响应:
      {
        "id": 15,
        "color_set": true,
        "n_colored": 500
      }

3.7.3 实现位置
────────────────────────────────────────────────────────────────

  C++ 端: src/remote/RemoteControlServer.cpp
    → scene.splats.create_sphere, .create_box, .create_points
    → scene.splats.load_file
    → scene.node.remove
    → scene.splats.set_color

  Python 端: remote_api/server.py
    → POST /scene/splats/create, /scene/splats/load
    → DELETE /scene/node/{id}
    → POST /scene/splats/{id}/color

  数据模型: remote_api/models.py
    → SphereParams, BoxParams, PointsParams
    → SplatsCreateRequest, LoadFileRequest, SetColorRequest

4.6 快速构建 (Windows)
────────────────────────────────────────────────────────────────

  前提: CUDA 12.4+, Visual Studio 2022 (17.10.3+), CMake 3.22+
  推荐 GPU: RTX 4070+ (RTX 5090(D) 验证通过)

    # 1. 配置 (生成 build/SplatEditor.sln)
    cmake -B build -S .

    # 2. 构建 Release 目标
    cmake --build build --config Release --target SplatEditor

    # 3. 从仓库根目录运行 (资源相对路径解析)
    ./build/Release/SplatEditor.exe

  4DGS 设置 (RTX 5090D + CUDA 13.2 快速路径):

    # 步骤 1: 下载 LibTorch cu128
    curl -L -o libtorch.zip \
      "https://download.pytorch.org/libtorch/cu128/libtorch-win-shared-with-deps-2.6.0%%2Bcu128.zip"

    # 步骤 2: 解压到 libs/libtorch (项目相对, CMake 自动探测)
    tar -xf libtorch.zip -C libs/

    # 步骤 3: 配置 & 构建
    cmake -B build -S .
    cmake --build build --config Release

4.7 LibTorch 版本兼容性
────────────────────────────────────────────────────────────────

  ┌──────────────┬─────────────────────┬──────────────────────────────┐
  │ 系统 CUDA    │ GPU                 │ 使用 LibTorch                │
  ├──────────────┼─────────────────────┼──────────────────────────────┤
  │ 12.4 – 12.7  │ RTX 30/40 系列      │ cu124 ✓                      │
  │ 12.8+        │ RTX 50 系列         │ cu128 ✓                      │
  │ 13.x         │ RTX 5090(D)         │ cu128 ✓ (驱动后向兼容)       │
  └──────────────┴─────────────────────┴──────────────────────────────┘

  关键: LibTorch 捆绑自有 CUDA 运行时 — 不依赖系统 CUDA Toolkit。
  系统 CUDA 版本仅需在驱动层面 >= LibTorch CUDA 版本。
  Splatshop 本身独立于系统 CUDA Toolkit 编译。


第5章  已知限制与未来方向
================================================================================

5.1 当前限制
────────────────────────────────────────────────────────────────

  • Alpha 学术原型 — 预计较多 bug 和崩溃
  • VR 仅 Windows — 未解决 Linux OpenVR 集成
  • 无球谐函数 — 内存需求大且增益有限 (未来探索更经济的 SH 方案)
  • CUDA Driver API — 启动缓慢 (运行时编译CUDA)
  • 撤销覆盖不完整
  • 变换撤销有损 — 尤其缩放 (缩小过多时精度丢失)
  • 应用冻结: RTX 20xx 系列已知问题 (线段渲染已修复,
    VR 三角网格可能仍有问题)

5.2 未来方向
────────────────────────────────────────────────────────────────

  项目目前的首要任务是收集反馈以确定功能和修复的优先级。
  已知的待完善区域:
    • 撤销/重做覆盖扩展到所有功能
    • 以无损精度重构平移/旋转/缩放撤销
    • Linux OpenVR 集成
    • 经济的球谐函数编码
    • NVENC H.264 视频流管道完善
    • 补全多缓冲分布的 Phase 2/3 特性
