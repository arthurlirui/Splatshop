# 物体运动控制模块设计方案

## 目标概览
为 Splatshop 增加两层运动控制能力：
1. **单体刚性物体控制**：通过统一 C++ 接口向场景中任意 `SceneNode` 下发「尺度 + 位移 + 旋转」，控制其刚体运动与姿态。
2. **人体高斯泼溅控制**：对带 rig 的人体 splat 节点，下发「骨架关节姿态 + ARKit 52 面部 blendshape 权重」，每帧做 LBS 蒙皮与表情变形驱动高斯运动。

四种调用形式：C++ API、关键帧/时间轴、外部输入（文件/流）、ImGui 面板。资产格式尚未确定，故方案对资产中立：定义运行时数据结构 + loader 抽象，先用程序化测试骨架验证管线。

## 现状关键事实
- 场景图 `SceneNode`（`src/scene/SceneNode.h:28`）以 `mat4 transform`（局部）+ `transform_global`（每帧由 `Scene::updateTransformations()` 累积）表示位姿；`SNSplats`（`src/scene/SNSplats.h:12`）持有 `GaussianDataManager dmng`。
- 每帧 `SplatEditor_draw.h:193` 把 `node->transform_global` 写入 `node->dmng.data.transform`，CUDA 内核 `gaussians_rendering.cu:472` 读取 `model.transform` 做刚性变换 —— 单体刚性控制的天然接入点。
- `kernel_apply_transformation`（`src/gaussians_editing.cu:251`）逐 splat 矩阵烘焙，可作为逐 splat 蒙皮 kernel 的模板。
- `TWEEN`（`src/tween.h:16`）是已有简易动画系统，`SplatEditor::update()` 顶部调用 `TWEEN::update()`。
- 无任何骨骼/蒙皮/blendshape 结构，需全部新建。
- CMake 通过 `file(GLOB ... src/*.* ...)`（`CMakeLists.txt:14-29`）自动纳入新源文件，新增文件无需改 CMake。

## 模块划分（新增目录 `src/motion/`）

### A. 公共数据结构 — `src/motion/MotionTypes.h`
```
struct TransformSample { vec3 translation; quat rotation; vec3 scale; };   // 单体位姿采样
struct JointPose { quat rotation; vec3 translation; vec3 scale; mat4 localMatrix(); };  // 关节局部位姿
struct SkeletonPose { vector<JointPose> joints; };                        // 整体骨架姿态
constexpr int BLENDSHAPE_COUNT = 52;                                       // ARKit
struct FaceData { float weights[BLENDSHAPE_COUNT]; };                      // 表情权重
```

### B. 单体物体控制器 — `src/motion/MotionController.{h,cpp}`
- `class MotionController` 持有 `Scene*` 引用，按 `NodeID` 索引控制目标。
- API（用户选择的「C++ API」）：
  - `setTransform(NodeID, const TransformSample&)` — 由 `translation/rotation/scale` 合成 `mat4`，写入 `node->transform`（仅设局部，不动父子链）。
  - `getTransform(NodeID) -> TransformSample` — 从 `node->transform` 用 `glm::decompose` 反解。
  - `setTranslation / setRotation / setScale / translate / rotate / scaleBy` — 分量便捷接口。
  - `setTransformAnimated(NodeID, target, double durationMs, EaseFn)` — 基于 `TWEEN` 的过渡（关键帧/时间轴的基础构件）。
- 在 `SplatEditor::update()` 中 `scene.updateTransformations()` **之后**、渲染之前无侵入：直接改 `node->transform`，下一帧 `updateTransformations()` 自动生效。无需改 draw 内核。

### C. 关键帧/时间轴 — `src/motion/Timeline.{h,cpp}`
- `struct TransformKeyframe { double time; TransformSample sample; };`
- `struct TransformTrack { NodeID target; vector<TransformKeyframe> frames; InterpMode mode; };`
- `class Timeline { vector<TransformTrack> tracks; vector<RigTrack> rigTracks; void update(double t); };` —— 在统一时间轴上插值，调用 `MotionController` 与 `RiggedHumanController`。`Timeline::update` 由 `SplatEditor::update()` 在 `TWEEN::update()` 之后调用。
- 抽象 `IInputStreamSource` 供「外部输入」实现（JSON 文件、网络/IPC 流），把外部数据翻译为 `TransformTrack`/逐帧 `setPose`。先实现 JSON 文件播放。

### D. 人体 rig 数据结构与控制器
新增节点类型 `src/scene/SNRiggedSplats.{h,cpp}`（继承 `SNSplats`）：
```
struct Skeleton { vector<string> jointNames; vector<int> parents; vector<mat4> inverseBindMatrices; };
struct RigAsset { Skeleton skeleton;                // 骨骼层级 + 逆绑定矩阵
                  shared_ptr<Buffer> boneIndices;   // per-splat 4 个 bone index (uint16)
                  shared_ptr<Buffer> boneWeights;   // per-splat 4 个权重 (float)
                  int blendshapeCount;              // 人体无表情则为 0
                  shared_ptr<Buffer> blendshapeDeltas; }; // 形变 delta（pos/rot/scale）
struct SNRiggedSplats : SNSplats {
    RigAsset rig;
    shared_ptr<Buffer> restPosition, restScale, restQuaternion;  // rest 副本（蒙皮源）
    shared_ptr<CudaBuffer> poseJointMatrices;      // GPU：当前帧全局关节矩阵
    SkeletonPose currentPose; FaceData currentFace;
    bool poseDirty = true;
};
```
- `class RiggedHumanController`：
  - `setPose(NodeID, const SkeletonPose&)`、`setFace(NodeID, const FaceData&)`、`setPoseAndFace(...)`。
  - `update()` 遍历所有 `SNRiggedSplats`，若 `poseDirty`：CPU 端按 `Skeleton::parents` 把局部 `JointPose` 累积成全局关节矩阵 `M_global[i]`，再乘 `inverseBindMatrices[i]` 得蒙皮矩阵 `M_skin[i]`，拷贝到 `poseJointMatrices` GPU buffer。

### E. 蒙皮/表情 CUDA kernel — `src/motion/skinning.cu` + `gaussians_editing.cu` 复用模式
新增 kernel `kernel_skin_splats`：
```
输入: restPosition/scale/quaternion, boneIndices/weights, poseJointMatrices[count],
      blendshapeDeltas + faceWeights, transform_global (root)
输出: 写入 node->dmng.data.position/scale/quaternion （现有渲染 kernel 直接读）
```
- 逐 splat：`p = Σ w_i * M_skin[i] * restPos`；四元数 `q = normalize(Σ w_i * q_i)`（`q_i` 从 `M_skin[i]` 旋转分量提取）；scale 沿用线性混合 + blendshape delta；面部 delta（若 `blendshapeCount>0`）按 `weights` 叠加位移/旋转增量。
- 接入点：`SplatEditor_draw.h` 现有 `scene->process<SNSplats>` 之前，新增 `scene->process<SNRiggedSplats>`（注意 `process` 用 `dynamic_cast`，派生节点会被命中），在 `node->dmng.data.transform = node->transform_global` 之前 launch 蒙皮 kernel。
- **不修改任何现有渲染内核**（用户选择的「每帧蒙皮 kernel + rest 副本」方案）：蒙皮 kernel 把变形结果原地写入 `dmng.data` 的 position/scale/quaternion，现有 `kernel_stageSplats_perspectivecorrect` 照常读取，仅 `model.transform` 设为单位（root motion 已并入蒙皮）。
- rest 副本由 loader 在加载时建立；如运行时调用现有「烘焙变换」编辑功能需同步更新 rest 副本，加 `SNRiggedSplats::syncRest()`。

### F. 资产加载抽象 — `src/loader/RiggedSplatsLoader.{h,cpp}`
- `struct IRigAssetSource { virtual RigAsset load()=0; };` —— 因资产格式未定，先定义抽象接口与最小实现：
  - `ProceduralRigSource`：程序化生成简单测试骨架（如 5 关节）+ 均匀/最近邻 bone weights，用于验证蒙皮管线不依赖真实资产。
  - 预留 `GLTFSkinRigSource` 占位（骨骼权重/IBP 从 GLTF skin 读，splats 仍用现有 .ply），后续填充。
- 复用现有 `GSPlyLoader` 加载 splat 主体，rig 数据从附带文件读取，组装为 `SNRiggedSplats` 节点加入 `scene.world`。drop 回调（`main.cpp:315`）扩展：识别 `.ply + 同名 .rig.json` 组合。

### G. ImGui 面板 — `src/gui/motion.h`
- 在现有 GUI 页面机制中新增 "Motion" 页（参照 `src/gui/editing.h` 模式）：
  - **物体位姿区**：选中节点的 translation/rotation/scale 数值输入（`ImGui::DragFloat3` 等），调用 `MotionController::setTransform`；按钮「播放测试动画」。
  - **人体 rig 区**：若选中 `SNRiggedSplats`，列出关节滑条（每关节 Euler/quat）+ 52 个 blendshape 滑条（折叠分组：眼/颌/嘴/颊/舌等），实时调用 `RiggedHumanController::setPose/Face`。
  - **时间轴区**：track 列表、播放/暂停/scrub、load JSON。

## 集成改动（最小侵入）
1. `SplatEditor.h`：增加成员 `MotionController motionController; RiggedHumanController rigController; Timeline timeline;`（`#include "motion/..."`）。
2. `SplatEditor_update.h:12` 之后插入：
   - `timeline.update(currentTime);`（时间轴驱动）
   - `rigController.update(scene);`（累积关节矩阵、标记 GPU 待更新）
   - draw 前 `rigController.dispatchSkinning(scene)` 或放在 draw 的 process 前。
3. `SplatEditor_draw.h:189` 的 `scene->process<SNSplats>` 前，对 `SNRiggedSplats` 调用蒙皮 kernel（注意先蒙皮再设 transform）。
4. `main.cpp` drag-drop（`:315`）：扩展 rigged 组合识别。
5. `src/gui/...` 注册 "Motion" 页（仿现有 page 注册点）。
6. CMake：无需改动（GLOB 自动纳入 `src/motion/*` 与 `src/motion/*.cu`；若 `.cu` 未被 GLOB 命中则补一条 `src/motion/*.cu`，与现有 `src/render/*.cu` 一致）。

## 实施顺序
1. `MotionTypes.h` + `MotionController.{h,cpp}` + `Timeline.{h,cpp}`（纯 CPU、不动 GPU），并在 update 中接入；ImGui 物体位姿面板。→ 可立即验证单体刚性控制。
2. `SNRiggedSplats` + `RiggedHumanController`（CPU 端骨架矩阵累积）+ `ProceduralRigSource`。
3. `skinning.cu` 蒙皮 kernel + draw 接入 + rest 副本管理。→ 验证程序化骨架驱动 splat 变形。
4. 面部 blendshape delta 叠加 + 52 滑条面板。
5. JSON 关键帧/外部流播放；后续按确定的资产格式实现 `GLTFSkinRigSource`。

## 风险与备注
- **SH 在非刚性变形下的鲁棒性**：现有代码注释已指出「SHs not yet robust under model and splat transformations」（`gaussians_rendering.cu:505`）。蒙皮属非刚性变形，SH 视线方向需用变形后法向/近似旋转修正。首版可对 rig 节点降级为 SH degree 0 或用蒙皮旋转近似修正 SH camdir，标注 TODO。
- **逐帧重写 dmng 缓冲**：蒙皮每帧覆盖 position/scale/quaternion，与「编辑模式烘焙」会冲突；编辑期间对 rig 节点禁用蒙皮或 `syncRest` 后再编辑。
- **性能**：每帧蒙皮 kernel 对全量 splat（含不可见）launch；可加 frustum/visible 早剔，但首版先按全量。
- **资产中立**：因格式未定，先以 `ProceduralRigSource` 跑通管线，`IRigAssetSource` 保证后续真实资产接入无需改控制器与 kernel。
