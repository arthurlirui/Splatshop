## 目标

修复 CMake 4.x 与捆绑 GLFW 3.3.2 的兼容性问题。本机 CMake 4.3 移除了对 `cmake_minimum_required` < 3.5 的兼容,而 GLFW 3.3.2 的 `CMakeLists.txt` 声明的最低版本过低,导致 `FetchContent_MakeAvailable(glfw)` 配置时报错中止。

## 改动

只改 `cmake/glfw.cmake` 一个文件。在 `FetchContent_MakeAvailable(glfw)` 之前设置 `CMAKE_POLICY_VERSION_MINIMUM=3.5`,让 CMake 接受 GLFW 3.3.2 的旧版本声明。

```cmake
cmake_minimum_required(VERSION 3.14)

include(FetchContent)

set(GLFW_BUILD_EXAMPLES OFF)
set(GLFW_BUILD_TESTS OFF)
set(GLFW_BUILD_DOCS OFF)
set(GLFW_INSTALL OFF)

FetchContent_Declare(
		glfw
		GIT_REPOSITORY      https://github.com/glfw/glfw.git
		GIT_TAG             3.3.2
)

# GLFW 3.3.2 declares cmake_minimum_required(VERSION 2.x), which CMake 4.0+
# no longer accepts. Allow the old policy version for the GLFW subproject only
# (scope limited to this directory before FetchContent_MakeAvailable).
set(CMAKE_POLICY_VERSION_MINIMUM 3.5)

FetchContent_MakeAvailable(glfw)
```

## 要点

- **作用域**:`set(CMAKE_POLICY_VERSION_MINIMUM 3.5)` 在 `cmake/glfw.cmake` 内、`FetchContent_MakeAvailable` 之前设置,只影响 GLFW 子项目的配置,不影响主项目 `CMakeLists.txt` 的策略行为。
- **不升级 GLFW**:保留 3.3.2,避免引入新版 API 变更的回归风险。GLFW 3.3.2 本身代码能正常编译,只是其 `cmake_minimum_required` 声明过旧。
- **跨平台**:此设置对 Windows 和 Ubuntu 都生效,两边的 CMake 4.x 都会遇到同一问题。

## 涉及文件

- `cmake/glfw.cmake` — 加 3 行(set + 2 行注释),在 `FetchContent_MakeAvailable` 前。

## 验证

- `cmake -B build` 重新配置,确认不再报 `cmake_minimum_required` 兼容错误,配置成功。
- 由于改动只涉及 CMake 配置层,无需重新编译源码;但若配置成功,可顺带 `cmake --build build --config Release` 确认 GLFW 及整个项目仍正常构建。
- 注意:本机当前网络无法访问 github.com(`FetchContent` 需克隆 GLFW),但 `build/_deps/glfw-src/` 已有缓存源码。配置时 `FetchContent` 检测到源码已存在会跳过下载,所以验证可进行。
